# План: transcriber.kahman.studio

Сайт для расшифровки звонков: записи из Заметок iPhone (и из мессенджеров) загружаются на сайт,
Gemini делает дословную расшифровку и итог разговора, итог собирается в Word.
Результат виден в профиле и приходит в Telegram.

## 1. Репозиторий и защита данных

- Корень репозитория — папка `call-transcriber`. `transcribe.py` и `make_docx.py` остаются на месте,
  чтобы локальный скилл `call-transcript` работал как раньше.
- `.gitignore` с первого коммита: `results/`, `data/`, `.env`, базы, аудио, `venv`.
  В репозитории только `.env.example` без значений. Адрес Cloudflare Worker — тоже в `.env`.
- Перед каждым пушем проверка, что в коммит не попали записи, имена клиентов и ключи.
- Коммиты от имени владельца, без упоминания Claude.

## 2. Ядро обработки

- `transcribe.py` — функция, которую вызывает сервер, и прежняя командная строка. Прогресс по кускам
  уходит на сайт.
- `summarize.py` — итог пишет Gemini по шаблону:
  - «Холодный звонок» — интерес, возражения, следующий шаг, оценка лида;
  - «Созвон с заказчиком» — как в скилле;
  - «Авто» — модель выбирает сама.
- Один Word на звонок: сначала итог, в конце полная расшифровка. Отдельно — `.txt` с расшифровкой.
- Каждая запись переводится в m4a, чтобы Safari проигрывал и перематывал любой формат (в том числе ogg из Telegram).

## 3. Сайт

- FastAPI, шаблоны Jinja, обычный JavaScript без внешних CDN, SQLite.
- Очередь — отдельный сервис `transcriber-worker`: «в очереди → расшифровка → итог → готово / ошибка».
  После перезапуска продолжает с последнего готового куска.
- Страницы: вход; история звонков (дата, собеседник, длительность, статус); загрузка нескольких файлов
  с полем «с кем разговор» и выбором шаблона; страница звонка; настройки.
- Страница звонка: плеер со скоростью 1× / 1.5× / 2×, нажатие на реплику перематывает запись,
  текущая реплика подсвечивается; вкладки «Итог» и «Расшифровка»; «Скачать» и «Поделиться» через меню iOS;
  перезапуск обработки при ошибке.
- Статус обработки обновляется сам.
- Аудио отдаётся с поддержкой Range (без неё iPhone не перематывает), только после входа.
- Мобильная версия в первую очередь: PWA с иконкой и отдельным окном, вырезы экрана, тёмная тема.

## 4. Безопасность

- Пароль — только хэш argon2id в `/etc/transcriber.env`. Задаётся одной командой владельцем,
  открытым текстом никуда не попадает.
- Сессии: случайный токен, в базе только его хэш; cookie HttpOnly + Secure + SameSite, 30 дней.
- CSRF-токен в каждой форме и проверка заголовка Origin.
- Перебор паролей: блокировка по IP с растущей паузой, общий лимит неудачных попыток, лимит запросов
  в nginx, fail2ban, сообщение в Telegram о подозрительных попытках.
- Второй фактор (TOTP): код из приложения-аутентификатора, запомненное устройство его не спрашивает.
- Загрузки: лимит размера, проверка ffmpeg, что это аудио; имена файлов генерирует сервер, файлы вне
  папки сайта; ffmpeg без shell.
- Бот принимает записи только из привязанного чата владельца; чат привязывается одноразовым кодом.
- Запросы к базе только с параметрами, автоэкранирование в шаблонах, строгая CSP без встроенных скриптов.
- HSTS, запрет встраивания в чужие страницы, запрет индексации.
- Отдельный системный пользователь `transcriber`, папка данных доступна только ему, ограничения systemd.
  uvicorn слушает только `127.0.0.1`, настоящий IP берётся только из заголовков nginx.

## 5. Telegram через Cloudflare

- Второй Worker (код в репозитории) пропускает только запросы к Bot API и только с секретным заголовком.
- Бот пишет только в чат владельца (`TELEGRAM_CHAT_ID`): «Готово» с итогом и Word во вложении,
  предупреждения о попытках входа.

## 6. Как запись попадает на сайт

Быструю команду iPhone убрали (24.10.2026): в iOS 26 её неудобно собирать. Вместо неё два пути:

- **Бот в Telegram.** Заметки → «Поделиться» → Telegram → бот. В подписи по желанию имя и тип
  («Иван», «Иван холодный», «Иван заказчик»). Бот отвечает «Принято», итог и Word присылает
  ответом на это сообщение. До 20 МБ — больше Telegram ботам не отдаёт.
- **Кнопка «Загрузить» на сайте.** Файл из «Файлов», до 300 МБ. Имя и тип — по желанию.

## 7. Сервер и автодеплой

- `deploy/bootstrap.sh` по образцу leadgen: пользователь, папки, venv, ffmpeg, сертификат, nginx,
  две службы systemd, fail2ban. Порт 8780.
- `deploy/deploy.sh` + GitHub Actions: пуш в `main` — сервер обновляется сам. Если новый конфиг nginx
  не проходит проверку, возвращается прежний (leadgen и основной сайт не ломаются).
- Отдельный SSH-ключ для деплоя.
- Ключи на сервере — в `/etc/transcriber.env`, не в git.

## 8. Проверка

- Локально: прогон настоящих записей, сайт в размере iPhone.
- Защита: блокировка после неверных паролей, отказ без CSRF-токена, попытки подсунуть свой путь
  к файлу, загрузка не-аудио, HTML в имени файла и в поле «с кем разговор».
- На сервере: HTTPS, заголовки, вход, обработка звонка, сообщение в Telegram.
- Владелец: сайт на главный экран, запись из Заметок через бота и через «Загрузить».

## Что нужно от владельца

1. Бот в @BotFather: токен + написать боту `/start`.
2. Cloudflare: вставить код Worker'а в панели (инструкция в `docs/telegram.md`).
3. GitHub: секрет `DEPLOY_KEY` (Settings → Secrets and variables → Actions).
4. Пароль: одна команда в терминале (`python tools/set_password.py`).
